Day 24 — Generics, Classes and Modules

The last exercise day of Week 5. Two of these files are not exercises — result.ts and repository.ts are the real thing, and Day 25's migration uses both.

How to run it

npm install
npm run dev        # then open the console (F12)
npm run typecheck  # 0 errors, with 9 deliberate ones pinned

The files

src/model.ts       carried forward from Day 23, unchanged
src/result.ts      Result<T, E> - a generic discriminated union
src/repository.ts  Repository<T> over localStorage
src/generics.ts    the ten sections

The dependency direction is one-way: model.ts and result.ts import nothing, repository.ts imports result.ts, and the exercises import all three. repository.ts does not know a Book exists — it takes a type parameter and a validator — which is why it could store something else tomorrow without being edited.

What the sections cover

  1. Why a generic, against any and unknown
  2. Inference, and when to be explicit
  3. Constraints with extends
  4. keyof constraints — pluck and groupBy
  5. A generic Store<S> class
  6. Parameter properties, private against #, protected, implements, this returns
  7. Result<T, E> and safeJsonParse
  8. The repository, with all five failure paths forced
  9. Generic defaults, and when a type parameter is just ceremony
  10. Module boundaries, import type, and the circular import I backed out of
