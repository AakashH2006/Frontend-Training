1. computed is lazy and cached

a = {{ a() }}, b = {{ b() }}, product = {{ product() }}

The computation has run {{ runsShown() }} {{ runsShown() === 1 ? 'time' : 'times' }}.

The template reads product() once per render and the button reads it three more times, and the run count does not move. A computed recalculates only when one of the signals it read has changed; every read in between returns the cached value.

2. A computed notifies only when its value changes

count = {{ count() }}, isEven = {{ isEven() }}

The effect watching isEven has run {{ evenChangesShown() }} {{ evenChangesShown() === 1 ? 'time' : 'times' }}.

+2 changes count and leaves isEven alone, so nothing downstream re-runs. +1 flips it and the effect fires. The graph propagates values, not invalidations — which is the thing useMemo does not do, because its consumers re-render whenever the component does.

3. untracked

readsOne = {{ readsOne() }}

readsOne reads both signals but only depends on the first. Changing the untracked one does not recompute it, so the displayed value goes stale on purpose — which is the point: untracked is for reading something you do not want to react to.

4. linkedSignal — writable and derived

options = [{{ statuses().join(', ') }}] · selected = {{ selected() }}

Select the last option, then change the options: the selection resets to the first of the new list. Writable like a signal, derived like a computed.

This is the shape that needed a useState plus a useEffect in React — a selection that resets when its options change — which is the pattern the React docs warn about and Day 34 removed with a key. Here it is one declaration.
