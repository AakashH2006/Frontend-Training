Day 23 — Object Types, Aliases and Interfaces

The day the types stopped being exercises and started being a model. The API's shape and the app's shape are two different things related by one function, and src/model.ts is where that lives.

Not run yet.

How to run it

npm install
npm run dev        # then open the console (F12)
npm run typecheck  # 0 errors, with 12 deliberate ones pinned

The two sets of types

OpenLibraryDoc   what the API sends - snake_case,
                 nearly everything optional, fields
                 this app has no use for

Book             what the app works with - camelCase,
                 nothing optional unless the UI
                 renders the missing case

toBook()         the only crossing point

Every ?? in toBook is a decision about a missing field. Writing the types out is what forced each one to be made on purpose rather than discovered later as a blank space on a card.

What the sections cover

  1. type against interface, and why Status has to be an alias
  2. Declaration merging, and why it argues for aliases in my own code
  3. extends against an intersection, and the never property
  4. Optional properties under exactOptionalPropertyTypes
  5. readonly, and how shallow it is
  6. Index signatures against Record, and closed lookup tables
  7. Structural typing, and branded types
  8. The API shape against the domain shape
  9. Pick, Omit, Partial, keyof
  10. Validating at the storage boundary
