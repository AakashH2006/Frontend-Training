1. Interpolation — {{ '{{ expression }}' }}

The title is {{ title() }}, {{ title().length }} characters.

Evaluated against the class and escaped on the way out. It accepts an expression, not a statement — no assignment, no ;, no function declaration. That restriction is the template language's whole design: logic belongs on the class.

2. Property binding — [property]

[disabled] sets the DOM property. Writing disabled="false" instead would set the attribute to the string "false", and a present disabled attribute disables the button whatever its value — so the plain version is permanently disabled. That is the single most common binding mistake and it fails in the direction that looks deliberate.

3. Attribute binding — [attr.name]

For attributes with no matching DOM property — every aria-*, colspan, role. Binding null removes the attribute entirely, which is how an optional aria-describedby is expressed.

4. Class and style binding

status-{{ status() }}{{ highlighted() ? ', highlighted' : '' }}

{{ progressLabel() }}

[class.x] toggles one class and leaves the rest alone. [class] with a string replaces the bound set — it does not touch the static class attribute, which is why both survive here.

5. Event binding — (event)

value: "{{ typed() }}" · last key: {{ lastKey() || '(none)' }}

Any DOM event name in parentheses. $event is the real event, typed — so a handler declaring KeyboardEvent is checked against the event the template actually binds.
